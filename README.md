# TripGo — лабораторные работы

## Запуск проекта

Из корня репозитория выполнить:

```bash
tripgoctl cluster start
tripgoctl environment start
tripgoctl connect
```

Применить миграции базы данных:

```bash
make migrate
```

Запустить сервис:

```bash
make run
```

## Конфигурация

Основные переменные окружения:

| Переменная | Назначение |
|---|---|
| `HTTP_ADDR` | Адрес HTTP-сервера |
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `LOG_LEVEL` | Уровень логирования |
| `SHUTDOWN_TIMEOUT` | Таймаут graceful shutdown |
| `DATABASE_MAX_CONNS` | Максимальное количество соединений с БД |
| `DATABASE_MIN_CONNS` | Минимальное количество соединений с БД |
| `DATABASE_CONNECT_TIMEOUT` | Таймаут подключения к БД |
| `DATABASE_QUERY_TIMEOUT` | Таймаут выполнения запросов |
| `DATABASE_MAX_CONN_LIFETIME` | Максимальное время жизни соединения |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Адрес OpenTelemetry Collector |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | Протокол экспорта телеметрии |
| `OTEL_TRACES_SAMPLER` | Стратегия семплирования трассировок |
| `OTEL_EXPORTER_OTLP_INSECURE` | Использование OTLP без TLS |

Фактические значения задаются в локальном окружении. Не добавляйте секреты и реальные учётные данные в репозиторий.

## Архитектура

Приложение разделено на слои:

- `internal/domain` — доменная модель и бизнес-правила.
- `internal/usecase` — сценарии приложения.
- `internal/repository` — доступ к данным.
- `internal/postgres` — подключение к PostgreSQL.
- `internal/txmanager` — управление транзакциями.
- `internal/http` — HTTP-обработчики и преобразование ошибок.
- `internal/httpserver` — HTTP-сервер, middleware, логирование и метрики.
- `internal/observability` — настройка OpenTelemetry и бизнес-метрики.
- `internal/config` — конфигурация приложения.

Доменный слой не зависит от HTTP и PostgreSQL. Ошибки домена преобразуются в соответствующие HTTP-ответы на уровне обработчиков.

## Транзакции и конкурентный доступ

### Уровень изоляции

Используется уровень изоляции `Read Committed`.

Запрет двух активных поездок у одного водителя обеспечивается уникальным частичным индексом по `driver_id` для записей со статусом `active`. Это ограничение сохраняется и при конкурентных запросах.

Ошибка PostgreSQL с кодом `23505` преобразуется в доменную ошибку `driver_busy`.

### Менеджер транзакций

Интерфейс:

```go
type TxManager interface {
    Do(ctx context.Context, fn func(ctx context.Context) error) error
}
```

Метод `Do` открывает транзакцию и передаёт её через контекст функции `fn`. При успешном выполнении выполняется `COMMIT`, при ошибке — `ROLLBACK`. При панике менеджер откатывает транзакцию и передаёт панику дальше.

## Обработка ошибок

Доменная логика не зависит от HTTP-статусов. HTTP-слой преобразует доменные ошибки в соответствующие ответы API.

Обработчики используют единый формат представления ошибок через пакет `internal/http/domainerror`.

## Проверка работоспособности

- `GET /health` возвращает `200 OK`, если процесс работает; проверка не обращается к базе данных.
- `GET /ready` проверяет доступность PostgreSQL и возвращает `503 Service Unavailable`, если база данных недоступна.

При получении `SIGINT` или `SIGTERM` сервер выполняет graceful shutdown с ограничением времени из `SHUTDOWN_TIMEOUT`.

## Observability

Для трассировок, метрик и корреляции логов используется OpenTelemetry.

### Трассировки

HTTP-запросы инструментируются для сбора трассировок. Операции с PostgreSQL представлены дочерними spans, связанными с соответствующим HTTP-запросом.

Трассировки можно просматривать в Jaeger. Для проверки создания поездки отправьте запрос через API и найдите соответствующий trace.

### Метрики

Собираются HTTP-метрики, в том числе:

- `http.server.request.duration` — длительность HTTP-запросов.
- `http.server.active_requests` — количество активных запросов.
- `tripgo.trips.created` — количество созданных поездок.
- `tripgo.trips.completed` — количество завершённых поездок.

В Prometheus имена счётчиков могут отображаться с суффиксом `_total`, например `tripgo_trips_created_total`.

Метрики можно просматривать через Grafana Explore, выбрав источник данных Prometheus.

### Структурированные логи

HTTP-логи содержат метод запроса, маршрут, HTTP-статус, длительность, `trace_id` и `span_id`. Это позволяет связать запись лога с соответствующей трассировкой в Jaeger.

### Работа без Collector

Сервис должен запускаться и обслуживать HTTP-запросы даже при недоступном OpenTelemetry Collector. В этом случае экспорт телеметрии может не выполняться, но запуск приложения не должен зависеть от доступности Collector.

## Миграции

Применить все ожидающие миграции:

```bash
make migrate
```

Откатить последнюю миграцию:

```bash
goose -dir migrations postgres "$DATABASE_URL" down
```
